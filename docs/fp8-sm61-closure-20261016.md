# FP8 E4M3FN on sm_61 — closure audit

Base: `fp8_candle` at `a4b5b3fb2474a6702e2791e753108ddd7839a8d5`.

## Integrated behavior

The R4D dispatcher, generic multi-shard inverse-scale loader, CUDA linear
operators and synthetic fixtures are integrated into the feature branch.
The original R4D archive's manifest hashes were checked before importing it.

The default stays SIMT W8A16. Resident FP16 expansion requires explicit opt-in,
a supplied measured workload/geometry profile, amortization of preparation,
and a model-wide VRAM budget reserving other weights, KV, workspace and headroom.
One operator keeps exactly one device weight representation. The residence
planner is a deterministic heuristic and does not claim optimal packing.
DP4A requantizes weights/activations and remains an explicit research mode.

Admission profiles must describe the actual device, numerical contract, workload
and implementation revision. Geometry alone does not make a profile transferable
between decoding, prefill, checkpoints or devices. Validate model logits and
argmax/quality independently before enabling an approximate backend.

## Corrections found during audit

- Reject FP16 weight expansion that turns a finite effective weight into infinity.
- Reject nonfinite effective FP32 weights before device allocation.
- Expanded F16 operands now use cuBLAS GEMM with **FP32 accumulation and FP32
  output**. The old `F16 matmul -> cast F32` could overflow the output or round
  it through FP16. A regression covers a finite sum above 65504.
- Check input/output counts and block dimensions against the CUDA signed i32 ABI.
- Reject mismatched Candle CUDA devices before launching kernels.
- Use overflow-safe CUDA ceiling division and share the standalone kernel header.
- Make the pure dispatcher, E4M3FN codec and checkpoint inventory usable/testable
  without enabling CUDA. Zero-sized malformed geometry returns an error.
- Preserve the examples feature alias and apply the ZIP 9 filename API migration.

SIMT and DP4A require contiguous zero-offset rank-2 FP16 activations. Expanded
GEMM now enforces the same layout contract. FP16 expansion rounds effective
weights to FP16; its numerical behavior is still distinct from SIMT.
